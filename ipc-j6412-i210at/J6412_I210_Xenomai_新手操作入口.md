# J6412 + Intel I210：Xenomai 新手操作入口

适用设备：四核 Intel J6412、Intel I210 PCIe 网口。参考系统：Debian 12 amd64。目标：先部署 Xenomai 3.3.1 Cobalt，验证 1 ms 和 125 μs 周期的实时唤醒；本轮暂不部署 EtherCAT。

逐条操作、命令、验证条件和故障处理都在 [完整操作手册](J6412_I210_Xenomai_移植与逐步验证手册.md)。本文帮助第一次操作的人确定顺序、文件位置和每阶段的交付结果。

## 1. 先理解需要安装什么

这次不是把一份补丁直接安装到现有 Debian 内核上，而是构建一套新内核和配套用户库：

```text
已经含 Dovetail 的 Linux 6.1.170 源码
                  +
Xenomai 3.3.1 的 Cobalt 内核代码
                  ↓ prepare-kernel.sh
带 Cobalt 的内核源码 → 配置 → 编译 → linux-image / linux-headers Deb 包
                  ↓ 安装并手动选择新内核启动
编译、安装同一版本的 Xenomai 用户库和 latency 测试工具
                  ↓
Cobalt 启动验收 → I210/igb 验收 → 1 ms/125 μs → 压力测试 → 调优与长测
```

原来的系统和旧内核负责提供构建环境、存储及回退启动入口。I210 在本阶段继续使用 Linux 的 `igb` 驱动。

## 2. 从哪里开始

先备份系统，准备本地显示器/键盘和能进入旧内核的 GRUB 菜单，再从完整手册的阶段 0 顺序执行。

已有源码位于 [Xenomai_Source_Packages](Xenomai_Source_Packages/源码包说明.md)，应把整个目录复制到目标 Debian 机。两个源码包为：

| 文件 | 固定版本 |
|---|---|
| `linux-dovetail-v6.1.170-cip55-dovetail1.tar.gz` | Linux 6.1.170-cip55 + Dovetail |
| `xenomai-v3.3.1.tar.gz` | Xenomai 3.3.1 |

同时复制 `SHA256SUMS`、`SOURCE_MANIFEST.json`。压缩包不包含 Git 历史，因此按完整手册 **4.2 节**校验和解压；完成后进入 **第 5 节**。4.3—4.5 节是不用归档、改走联网 Git 的替代说明，本次可跳过。

所有 Bash 命令在目标 Debian 终端执行；Windows PowerShell 只用于文件传输。使用普通用户编译，系统安装时使用 `sudo`。不要在 NTFS/U 盘上直接编译；把源码解压到 Debian 的本地 Linux 文件系统。构建路径不要含空格或中文，建议使用主手册默认的 `~/src/xenomai-j6412`。

## 3. 按这张表逐阶段操作

下表的“手册位置”指完整操作手册的章节；每阶段通过后再进入下一阶段。

| 阶段 | 手册位置 | 主要操作 | 必须看到的验证结果 |
|---|---|---|---|
| 0：硬件与恢复 | 第 2 节 | 确认四核、I210，备份 /boot 和 GRUB | CPU0—3 在线；I210 PCI 设备存在；旧内核能启动 |
| 1：编译环境 | 第 3 节 | 安装依赖、检查内存和磁盘 | 必需工具齐全；空间满足构建；Secure Boot 处理已确认 |
| 2：源码包 | 4.1、4.2 节 | 复制、校验、解压、记录来源 | 两个 SHA256 均为 OK；Dovetail 头文件和 prepare-kernel.sh 存在 |
| 3：接入 Cobalt | 第 5 节 | 执行官方接入脚本、检查链接和配置入口 | 脚本成功；Xenomai Kconfig 可读；没有断链；接入差异留档 |
| 4：内核配置 | 第 6 节 | 基于现有系统配置启用 Xenomai/Dovetail、保留硬件驱动 | 最终配置包含所需符号；I210 的 IGB=y/m；kernelrelease 已记录 |
| 5：构建和安装 | 第 7 节 | 编译 Deb 包，固定旧内核为默认，再安装新包 | 镜像、模块、initrd 和菜单齐全；默认仍指向旧内核 |
| 6：新内核首启 | 第 8 节 | 在 GRUB 手动选择新内核，检查 Cobalt 和 I210 | uname 对应新内核；/proc/xenomai 可读；I210 仍使用 igb |
| 7：配套用户库 | 第 9 节 | bootstrap、configure、编译和安装用户库 | xeno-config 为 3.3.1/cobalt；latency 的库没有 not found |
| 8：空闲基线 | 第 10 节 | 先 1 ms，再 125 μs；每轮保留日志 | 完整结束；RTS 汇总有 min/avg/max；overrun=0；模式切换已检查 |
| 9：压力与自检 | 第 11 节 | CPU/内存压力、I210 双向普通网络流量、xeno-test | 压力覆盖测量区间；无超期、驱动重置、硬件/热异常 |
| 10：优化和长测 | 第 12 节 | 对比 IRQ、频率、BIOS、隔离策略，完成 24/72 小时测试 | 最终配置满足唤醒预算；日志齐全；冷启动后可重复 |

普通用户权限配置见 8.3 节，首次部署应先用 `sudo` 完成基线，再单独验收普通用户权限。任何一步失败，都先保留日志并查看完整手册第 13 节；启动失败按第 16 节回退。

## 4. 成功后的文件应在哪里

以下目录均在目标 Debian 机上，`~` 表示当前普通用户的主目录。

```text
~/src/xenomai-j6412/
├── linux-dovetail/              Linux/Dovetail，已接入 Cobalt
├── xenomai-3.3.1/               同一版本的 Xenomai 源码
├── build-j6412/                 内核 .config 和构建结果
├── build-xenomai/               用户库构建目录及 config.log
├── planned-kernelrelease.txt    本轮内核的实际名称
├── linux-dovetail-commit.txt    Linux 源码提交记录
├── xenomai-commit.txt           Xenomai 源码提交记录
├── kernel-build.log            内核编译日志
└── linux-*.deb                 生成的内核安装包，以实际文件名为准

~/xenomai-migration-record/      备份、来源清单、硬件记录和测试日志
/usr/xenomai/                   安装后的 Xenomai 库、头文件和工具
/boot/                          新旧内核与 initrd；旧内核必须保留
```

默认接入脚本建立源码链接，两棵源码树在构建期间都要保留且不能移动。不要把仅含 `build-j6412` 的目录当作完整可复建源码。

如果交付时还需要一份可重放的 Cobalt `.patch` 文件，完整手册第 5.3 节提供了选做的导出、干净源码副本上的预检查和重放步骤；补丁只适用于本次固定的 Dovetail 基线。通常的安装交付物仍是第 7 节生成并验收的内核 Deb 包。

## 5. 如何判断“125 μs 通过”

125 μs 对应每秒 8,000 次周期唤醒。测试能启动只说明能够设置该周期；验收还需关注整轮最坏唤醒延迟、`overrun`、`msw`、温度、硬件日志和压力是否持续。

本阶段的最低要求是：空闲和所需压力条件下，测试完整结束、`overrun=0`，模式切换已定位，最大唤醒延迟低于项目分配的预算。未制定预算时，主手册提供 25 μs 作为临时排查阈值，不能当成该 CPU 的性能承诺。

未来控制应用还须满足：

```text
观测并评估的唤醒延迟 + 应用最坏执行时间 + I/O 时间 + 安全余量 < 125 μs
```

有限时间的 latency 测试不能证明理论最坏情况；本轮没有验证 EtherCAT 收发与从站。只有目标机测量完毕后才能填写通过与否。

## 6. 交付和回退

每台设备归档：原始两个源码包、来源清单、最终内核配置、实际 kernelrelease、Deb 包及校验值、用户库配置日志、BIOS/启动参数/IRQ 记录、原始测试日志和阶段验收表。操作记录格式见完整手册第 15 节。

新内核无法启动时，在本地 GRUB 高级选项选回旧内核；成功恢复后检查存储与 I210，保留失败日志再排障。不要删除旧内核或在尚未验收时把新内核设为唯一启动选择。新内核通过全部验收后，再按第 16.1 节设置默认启动项。

本文及完整手册已整理为操作规程；当前尚未在用户的 J6412 实机上编译、安装或进行实时性能测试。
